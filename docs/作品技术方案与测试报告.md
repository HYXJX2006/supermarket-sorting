## 一、项目概述

### 1.1 赛题背景

- **赛题编号**：DG-202606
- **发榜单位**：锐捷网络股份有限公司
- **赛题名称**：面向智慧零售的自主服务机器人研发与应用
- **赛事**：「挑战杯」揭榜挂帅专项赛擂台赛

### 1.2 任务定义

机器人在**仿真超市**环境中完成「**取货 → 搬运 → 投放**」闭环：

| 环节 | 内容 |
|---|---|
| 输入 | 系统下发 **5 个目标商品**（按品类，如 `pingguo` / `kele` / `shupian` 等） |
| 环境 | 5 排货架（A~E），共 **45 个货位**，商品随机分布；走廊存在**随机障碍物** |
| 输出 | 将目标商品从货架搬运到配送台桌面，全程无人工干预 |

### 1.3 评分规则（官方 referee 真值判定）

**流程制计分**：一个完整流程 = 把一件商品从货架搬到配送台，含 5 个**有序**步骤，必须按序完成不可跳步；**只有走完 S5 才结算一次得分**。

| 步骤 | 判定条件 | 分值 |
|---|---|---|
| **S1** | 底盘到达取货区（`zones.picking`） | +1 |
| **S2** | 机械臂够到目标 | +2 |
| **S3** | 目标被夹持并撤出货架（水平位移 > 0.20 m） | +6 |
| **S4** | 底盘进入配送区（`zones.delivery_base`） | +1 |
| **S5** | 物体放入桌面判定框并静止（线速度 < 0.02 m/s） | +10 |
| **B1** | 直立加分（倾角 < 15°） | +5 |
| **合计** | 单目标满分 | **25** |

**扣分项**：

| 事件 | 判定 | 扣分 |
|---|---|---|
| C1 | 撞到结构 | −5 |
| C2 | 碰倒其他商品（倾角 > 30° 或位移 > 0.05 m） | −5 |
| C3 | 搬运掉落（高度 < 0.30 m 判掉落） | −3，且**流程作废** |

**时限**：`referee.py: time_limit_s = 420.0`（**7 分钟**），到时强制结束、进行中的流程不计分。

## 三、核心技术方案

### 3.1 感知与目标定位

**技术路线**：YOLO 2D 检测 → RGB-D 反投影 → 世界坐标 → 槽位吸附校验

1. **YOLO 检测**：YOLOv8s 微调 9 类，输出 2D 检测框 + 置信度
2. **深度反投影**：结合深度图与相机内参，将框中心反投影为相机系 3D 点
3. **坐标变换**：相机外参 → 机器人基座 → 世界坐标
4. **表面→中心修正**：RGB-D 点落在商品朝机器人一侧的**可见表面**，需沿前进方向补偿到商品中心（逐类 `surface_to_center_fwd` 参数）
5. **槽位吸附**：将检测坐标吸附到最近的同类货位真值，消除检测抖动（实测最大 8 cm 偏差）

**实测精度**（吸附日志）：

| 方向 | 误差 |
|---|---|
| y（前后） | 8.0 ~ 8.5 cm |
| z（高度） | 8.9 cm |
| 综合 | 最大 11.2 cm |

> **关键设计决策**：由于任务只要求「品类」（任意同类副本有效），而货位坐标是布局真值，因此实现了**就近同类货位真值兜底** —— 吸附未命中时直接取离机器人最近的同类货位真值坐标，避免使用视觉估计值。

### 3.2 逐类抓取几何标定（核心技术资产）

**问题**：9 类商品形状、尺寸、质量差异极大（从 0.073 kg 的口香糖到 0.643 kg 的脉动），统一的抓取参数无法覆盖。

**方案**：建立**逐类几何参数数据库**，每类记录：

- `surface_to_center_fwd`：表面点到商品中心的进深补偿
- `deploy_offset`：预抓取末端相对商品中心的 (x, y, z) 偏置
- `creep_stop_dy`：creep 阶段停止线偏置
- `creep_speed`：接近速度（逐类标定）
- `grip_close`：夹爪闭合目标值（预压控制）
- `grip_feedback_max/min`：抬升门禁阈值（夹空检测）

**夹爪开口换算（基于官方 MJCF，非经验值）**：

```
腱位移 feedback 与两指开口的固定线性关系：
    两指开口(m) = feedback / 12.5      最大开口 0.08 m（feedback = 1.0）
来源：mmk2_options.xml 腱约束 rgt_gripper_gear = -12.5*左指 + 12.5*右指
```

**抬升门禁推导**：

```python
grip_gate_for_opening(opening_m) = max(0.85, opening_m × 12.5 × 1.12)
```
- `×1.12`：留 12% 余量吸收 MuJoCo 接触求解的 ±3% 波动
- **门禁只决定"是否允许尝试抬升"，不构成抓取成功判定** —— 成功以裁判遥测（物体 z 上升）为准

**9 类商品几何参数表**：

| 品类 | 形状 | 包络尺寸 (m) | 质量 (kg) | 表面距 (m) | 抓取速度 (m/s) | grip_close | 抬升门禁 | 夹空下限 | 标定 |
|---|---|---|---|---|---|---|---|---|---|
| 三明治 `sanmingzhi` | 三棱柱 | 0.065×0.100×0.099 | 0.122 | 0.0050 | **0.12** | 0.08 | 0.91 (推导) | 0.70 | ✅ |
| 合味道 `heweidao` | 圆台 | 0.095×0.095×0.105 | 0.099 | 0.0400 | 0.15 | **0.22** | 0.99 (手工) | 0.50 | ✅ |
| 薯片 `shupian` | 圆柱 | 0.065×0.065×0.210 | 0.137 | 0.0325 | 0.15 | 0.08 | 0.91 (推导) | 0.60 | ✅ |
| 纸巾 `zhijin` | 长方体 | 0.172×0.085×0.088 | 0.130 | 0.0425 | 0.15 | 0.08 | 0.85 (手工) | — | ❌ |
| 脉动 `maidong` | 圆柱 | 0.065×0.065×0.210 | **0.643** | 0.0325 | **0.12** | **0.050** | 0.90 (手工) | 0.70 | ✅ |
| 可乐 `kele` | 圆柱 | 0.053×0.053×0.145 | 0.357 | 0.0265 | 0.15 | 0.08 | 0.85 (下限) | 0.60 | ✅ |
| 口香糖 `kouxiangtang` | 圆柱 | 0.049×0.049×0.080 | 0.073 | 0.0245 | 0.15 | 0.08 | 0.85 (下限) | 0.60 | ✅ |
| 苹果 `pingguo` | 球 | 0.070×0.070×0.070 | 0.251 | 0.0350 | 0.15 | 0.08 | **0.98 (推导)** | 0.75 | ✅ |
| 橙子 `chengzi` | 球 | 0.074×0.074×0.074 | 0.253 | 0.0370 | 0.15 | 0.08 | **1.04 (推导)** | 0.85 | ✅ |

> **门禁判据**：`lift_controller` 中判定为 `feedback <= grip_feedback_max` 才允许抬升。
> "推导"值 = `max(0.85, 抓持宽度 × 12.5 × 1.12)`；"手工"值为实测标定后单独放宽。
> 橙子推导值 1.04 超出反馈上限 1.0，等效于**不设抬升门禁**（其抓取靠夹空下限 0.85 兜底），
> 这一点在答辩时可作为"门禁与真值分离"的实例说明。

**关键标定结论（答辩亮点）**：

1. **脉动（0.643 kg）的预压最优曲线**：0.060 太松滑落 / 0.040 过紧压歪（倾角 27°）/ **0.050 成功**（抬升 41.6 mm）—— 重物必须带预压
2. **苹果门禁修正**：球径 0.0700 → 理论反馈 0.875，高于通用门禁 0.85，导致**每次都被误拒**；改用逐类推导门禁后解决
3. **薯片高度补偿**：实测手部刮到下层板前沿（ee_y 卡住，每秒仅 0.5 mm），`dz` 从 −0.010 抬到 +0.030 后解决
4. **三明治表面距修正**：原按 y 深一半估算 0.0500 是错的，从 MJCF mesh 顶点算出真实表面距仅 **0.00775**（原值使停止线超前 0.093 m，夹爪一路顶推推走商品 12.2 cm）
5. **纸巾（zhijin）几何不可行**：夹爪最大开口 0.08 m，商品最小边 0.085 m —— **物理上无法合拢**，属已知无解项

### 3.3 动作编排状态机

**完整流程**（扫描完成后，每个目标循环执行）：

```
① target_nav       导航到货架观察位
② pregrasp_nav     接近预抓取位
     a. 目标导航到位
     b. 反向退出到机械臂安全预抓取线（倒车）
     c. 回正朝向（对齐货架法线）
③ pregrasp_stable  等待 odom 连续稳定 N 帧
④ plan_gate        plan-only IK 预演（先算不执行，安全的代价）
⑤ 抓取动作链       safe_pose → deploy → servo → creep → servo
                   → close_gripper → lift → retreat → slide_reset
⑥ deliver          配送导航（A* 路径 + 避障）
⑦ place            放置到配送台桌面上方
⑧ post_place       分阶段离开配送台 → 折叠手臂 → 复位
⑨ 下一目标
```

**两阶段手眼伺服**（`hand_eye_servo_controller.py`）：
- **进深前校准**：deploy 前用视觉微调，防止推歪商品
- **抓取面微调**：creep 后用 **j3 关节**（水平面关节）+ 升降柱修正横向漂移，**不重新部署**

**深度探测回路**（应对闭爪落空）：闭爪落空 → 进深 +1.5 cm → 重新 creep → close，最多 4 次，取代不可靠的表观尺寸测距。

**类别错配守卫**：目标位置没有本类检测却有别的类 → 提前报错换候选，拦截过 YOLO 把口香糖/脉动误认成橙子的盲抓。

### 3.4 导航与避障

| 机制 | 实现 |
|---|---|
| 全局路径 | **A\*** 预规划（`--planned-route`），航点序列驱动 |
| 局部避障 | 雷达反应式（`--obstacle-distance` / `--avoid-clearance`） |
| 朝向对齐 | 分模式容差（`--yaw-tolerance`），多窗口模式（巡航 / 巡游 / 货架接近 / 配送） |
| 卡死脱困 | 位置 12 s 不动 → 杀导航 → **倒车 2 s** → 重新驱动 |
| 失败恢复 | 导航连续失败上限（`NAV_RETRY_MAX`）→ 目标标记失败 → 继续下一目标 |

**多模式导航参数**（从运行日志）：

| 模式 | 速度 | 目标容差 | 避障距离 | 离障余量 |
|---|---|---|---|---|
| 扫描巡游 | 0.6 m/s | 0.05 m | 0.35 m | 0.55 m |
| 货架接近 | 0.6 m/s | 0.05 m | 0.35 m | 0.55 m |
| 配送 | 0.8 m/s | 0.18 m | ≤0.35 m | 0.30 m |

### 3.5 安全性设计（贯穿全程）

1. **plan-only 门禁**：所有真实动作先跑一遍 `plan-only`（只输出计划不发命令），IK 预演通过才允许执行
2. **夹空检测**：闭爪后读腱位移反馈，低于逐类下限（`grip_feedback_min`）= 指头越过商品 = 没夹到 → 不进入配送
3. **硬超时保护**：每个动作 worker 有独立超时（90 s），挂死则强制终止并继续流程
4. **失败继续**：单目标失败不中断整轮（`失败跳过，继续下一目标`）
5. **裁判遥测记录器**：每轮把商品侧地面真值写入 `debug_data/random5_telem/<时间戳>/`（gameinfo / target_state / joint_states / odom），保证任何失败都可复盘

### 3C.1 数据流与关键 ROS 话题

```
[Server 侧]                                     [Client 侧]

雷达 ────────────► /slamware_ros_sdk_server_node/scan ──► 导航避障
                                                          │

                                                          │
里程计 ──────────► /slamware_ros_sdk_server_node/odom ─► 导航 / 倾角监控
                                                          │
裁判 ────────────► /referee/taskinfo ──────────────────► executor（任务清单）
                   /referee/gameinfo ──────────────────► 计分遥测
                                                          │
[Client 侧下发命令]                                        ▼
底盘速度 ◄──────── /cmd_vel ◄────────────────────────── low_speed_navigator

```

**注意**：机械臂命令是 **7 个值**（6 关节 + 1 夹爪腱），少一个会被 server 拒绝
（`[ERROR] MMK2_mujoco_node: right arm command length error`）。

### 3C.2 主状态机（phase 流转）

`inventory_competition_executor.py` 用 `self.phase` 驱动：

| phase | 作用 | 出口条件 |
|---|---|---|
| `mapping` | 巡游扫描 45 货位建图 | `observed == 45` 或建图超时 |
| `target_nav` | 导航到目标货架观察位 | 导航到位 / 失败重试超限 |
| `pregrasp_nav` | 反向退出 + 回正 + 进预抓取位 | 到位 → `pregrasp_stable` |
| `pregrasp_stable` | 等 odom 连续稳定 N 帧 | 稳定 → `plan_gate` |
| `plan_gate` | plan-only IK 预演 | 通过 → `arm` |
| `arm` | 抓取动作链（`ARM_ACTIONS` 顺序推进） | 全部 done → `deliver` |
| `deliver` | 配送导航（A* + 避障） | 到位 → `place` |
| `place` | 放置 | 完成 → `post_place_safe_pose` |
| `post_place_safe_pose` | 离开配送台 + 折叠臂 | 完成 → 下一目标或 `done` |

**抓取动作链**（`ARM_ACTIONS` 元组，逐项 spawn worker）：
```python
ARM_ACTIONS = ("safe_pose", "deploy", "servo", "creep", "servo",
               "close_gripper", "lift", "retreat", "slide_reset")
```

### 3C.3 Worker 子进程机制

每个动作是一个**独立子进程**（`_spawn_arm(action)` → `subprocess.Popen`）：

- **优点**：动作之间完全隔离，单个动作崩溃不影响主进程
- **超时保护**：`ARM_WORKER_HARD_TIMEOUT`（90 s），超时强杀并继续流程
- **通信**：worker 通过 ROS 话题发布状态（`*/status`），executor 订阅推进状态机
- **plan-only 支持**：worker 接受 `--execute --confirm <action>` 双确认才发真实命令

### 3C.4 关键算法逻辑

**① 抓取目标点解算**（`grasp_deploy_controller`）：

```python
# 1) RGB-D 表面点 → 商品中心（沿前进方向补偿）
center = surface_point + surface_to_center_fwd * approach_dir

# 2) 加上预抓取偏置
deploy_world = center + deploy_offset        # (dx, dy, dz)

# 3) 位姿 = 位置 + 固定抓取姿态矩阵 GRASP_ROT（side 模式 = 单位阵）

# 4) KDL 逆运动学求解 6 关节角 → 平滑插值下发（ramp 1.5 s）
```

**② 抓取门禁判定**（`lift_controller`）：

```python
allow_lift = (feedback is not None) and (feedback <= grip_feedback_max)
empty_grip = (feedback < grip_feedback_min)      # 夹空检测
```
- `feedback` = 夹爪腱位移（`right_arm_eef_gripper_joint`），与两指开口线性相关
- **门禁只决定"是否允许尝试抬升"**；抓取是否成功以裁判遥测（物体 z 上升）判定

**③ creep 三轴停止判定**（`grasp_creep_controller`）：

```python
# 前后距离 = 目标停止线 - 末端 y
distance = stop_y - ee_world[1]

# 到达停止线后先对齐朝向（避免残余偏航被误判为横向偏差）
if abs(heading_error) > 0.06: 转向; return

# 再检查三轴误差（x 容差放宽到 0.070，兼容底盘反馈离散）
errors = target_world - ee_world
tolerances = (max(..., 0.070), y_tolerance, max(...))
if 任一轴超差: 报"到达停止线但末端未对准"; 否则停车成功
```

**④ 手眼伺服**（`hand_eye_servo_controller`，两阶段）：

```
阶段1（deploy 前）：进深前校准 —— 视觉微调，防止推歪商品
阶段2（creep 后）：抓取面微调 —— 用 j3 关节（水平面）+ 升降柱修正横向漂移，
                              不重新部署（避免大姿态变化）
```

**⑤ 槽位吸附与真值兜底**（executor）：

```python
snapped = _snap_to_slot(kind, world)      # 吸附到最近同类货位真值
if snapped: 用真值
else:       用最近同类货位真值（就近兜底）
            # 任务只要求品类，任意同类副本有效 → 真值精度远高于视觉
```

### 3C.5 参数覆盖机制（不改代码即可标定）

所有几何参数支持环境变量覆盖，命名规则：

```
SUPERMARKET_<KIND>_<PARAM>
例：SUPERMARKET_MAIDONG_GRIP_CLOSE=0.050
    SUPERMARKET_PINGGUO_GRIP_FEEDBACK_MAX=0.98
    SUPERMARKET_SANMINGZHI_CREEP_SPEED=0.12
```

实现见 `grasp_geometry.py: _kind_geometry()` —— 先用官方 MJCF 元数据构造基础值，再用环境变量覆盖，保证**形状/尺寸等物理事实不被改写**。

### 4.3 已识别问题（答辩时建议如实说明）

| 问题 | 根因 | 现状 |
|---|---|---|
| **配送段卡死** | 机械臂在配送时保持前伸姿态，车体实际外廓远大于避障模型假设的底盘半径，蹭到走廊随机障碍被楔住 | 有"倒车脱困"兜底，但会反复触发；根治需"运输姿态收臂"或"按机械臂外廓计算避障余量" |
| **C1 撞到结构** | 抓取接近时机械臂蹭到货架结构（−5 分） | 已排除"层板前沿"假设（抬高抓取点无效） |
| **时限压力** | 单目标约 4–6 分钟（含导航），而比赛时限 420 s | 需进一步压缩导航与停留时间；跳扫描方案因导航模式问题暂缓 |
| **视觉定位精度** | 检测 3D 坐标偏 8–11 cm（主要 z 深度） | 用槽位吸附 + 就近真值兜底规避，未根本改善 |

## 六、工程实践与创新点

### 6.1 可复用的工程方法

1. **逐类参数化**：用 `SUPERMARKET_<KIND>_*` 环境变量覆盖通道，使标定结果可版本化、可回滚，不需要改代码
2. **门禁与真值分离**：把"允许尝试"的门槛（`grip_feedback_max`）与"成功判定"（裁判遥测）彻底分开，避免门禁误杀成功抓取
3. **几何换算优先于经验值**：夹爪开口↔腱位移的关系从官方 MJCF 推导（`×12.5`），不是试出来的
4. **plan-only 先行**：真实动作前必须通过 IK 预演，把"能不能做"与"做了没有"分成两个阶段
5. **遥测全留档**：每轮失败都有商品侧地面真值可复盘，不依赖主观判断

### 6.2 技术难点与解法对照

| 难点 | 解法 |
|---|---|
| 9 类差异极大的抓取 | 逐类几何标定 + 预压曲线扫描 |
| 视觉深度误差 9 cm | 表面→中心修正 + 槽位吸附 + 就近真值兜底 |
| 闭爪落空 | 深度探测回路（+1.5 cm 递进，最多 4 次） |
| 误检导致盲抓 | 类别错配守卫（位置与品类交叉校验） |
| 高重心平台翻车 | 逐类接近速度上限（0.15/0.12）+ 分层限速 |
| 空手配送 | 逐类夹空检测下限（`grip_feedback_min`） |
| 卡死无人知 | 位置 12 s 不动检测 + 倒车脱困 |
