## 2. 回答：为什么每次从起点出发都要“先左走一点、再回正、再直走”

**一句话：这不是漂移，是导航策略里的“先转向面对航段再前进”，而第一条航段要求车头朝西，可车出生时朝北，且那条横移段本身只有 8 cm 却要付一次 90° 原地转向的代价。**

日志实证（21:32 那轮，`docker logs random5_autopilot_client`）：

```
pos=(1.92,-3.17) yaw=+90°  ← 出发姿态：朝 +Y（北）
[exec] drive 段 → (1.700,-3.170,yaw=3.14)   ← 第 1 航点要求朝西（π）
pickup-transit turn-in-place pos=(1.92,-3.17) dist=0.22 heading_err=1.49
pickup-transit turn-in-place ... heading_err=1.20 / 1.00 / 0.60 / 0.33   ← 原地左转（逆时针）约 3~4 s
到达位置，正在对齐朝向 yaw=2.96 err=0.18    ← 到位后再次原地对齐
```

机理链条：

1. 出生点 `(1.92, -3.17)`，yaw = +90°（北）。第一条航段是从起点“**向西退回** bypass 线 x=1.70”——横向只有 **22 cm（实测到位 1.85，仅走了 7 cm 就触发轴向到位门禁）**。
2. `low_speed_navigator` 的策略是“航点切换先原地完成 90° 转向，禁止带着上一段前进惯性”（`low_speed_navigator.py` L461-474、L584-596）。所以为这点横向位移付了一次 ~90° 原地转向，`--max-angular 0.45 rad/s` → 理论 3.5 s，实测含收敛 4~5 s。
3. 转向过程中前进速度非零（`turn-in-place` 与直行切换附近），车沿弧线漂了一点（实测 x 1.92→1.85 同时 y 上移），看起来就是“左走一点”。
4. 到第 3 个航点 `(x, 1.90)` 又要转向 ±X；到观察线 `(x, 2.40)` 再回正 +Y。于是整段像“左→回正→直走”，而且每个货架前都会重演。
5. 另外 `_goto_observe` 首段还硬编码 `bypass_x=1.70`、`start_x=1.92`（`inventory_competition_executor.py` L1450-1464），并没有拿当前 odom 算第一航点，所以从出发区出发/从配送区返回两条路径的“多余横移”都写死了。

代价估算（仿真时间）：每次 90° 原地转向 3.5~5 s，一次取送循环至少 2~4 次；一轮 5 单光转向就 40~80 s，占 420 s 的 10~20%。这也正好压着“无间歇连续作业”那 10 分。

**三个改法（按性价比排序，建议一次只改一个、跑一轮、读遥测、看窗口）：**

1. **消灭第一段横移（✅ 已实施并实测，见 §5）**：`bypass_x` 不要用常量，直接取当前 odom 的 x（或令 bypass 起点 = 当前位姿），第一个航点就与车同 x 同朝向 → 起步直接北上，第一次转向从“90° 为 22 cm”变成“0°”。`_return_route` 早已用 `current = (self.x, self.y)` 做 A* 起终点，无需改。
2. **转向提速 + 允许小幅转弯中前进**：把 `--max-angular` 从 0.45 提到 0.7~0.9，并把 `turn-in-place` 的门限从 `abs(err)>0.30` 放宽到与 `pickup_transit` 一致的 0.25/0.8（转向期间给 `linear.x = 0.15*alignment` 的弧线速度）。风险：底盘点动急、定位残差变大——**必须先在不抓取的空跑里量一次转向耗时与到位残差**再合并。
3. **同向航段合并**：`_goto_observe` 里 `(bypass_x,start_y)` 和 `(bypass_x,1.90)` 本就同向（都朝 +Y），只因为 x 差 7~22 cm 被拆成两段；改成“横向误差 < 8 cm 时直接跳过该航点”。注意 `transit_axis_done` 的容差 0.16 m 已经在偷偷这么干了，只是补偿逻辑没跟上——把它显式化。
