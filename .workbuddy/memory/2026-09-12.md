## 00:10 机械臂"固定偏左 5cm"的根因与修复（主人观察 → 代码级确认）

**主人观察**：机械臂每次都在商品左侧 ~5cm（系统性偏差，非随机）。

**代码级根因**（grasp_creep_controller 驱动段）：
```python
command.linear.x  = 前后距离控制          # 只有 y（进深）
command.angular.z = 2.0*(π/2 - yaw)      # 朝向锁死"垂直货架"
```
**creep 全程没有 x（横向）修正** —— 导航遗留的横向偏差（导航容差内 5cm）
被原样带到抓取点，而停止判定的 x 容差是 `max(..., 0.070)` = **7cm**，
5cm 偏差正好落进去 → creep 认为"对准了"就停车 → 夹取偏 5cm。

**修复**：载线修正（pure pursuit）——朝向目标从固定的 π/2 改为
`π/2 + atan2(横向误差, 前后距离)`，逼近过程中逐步把横向偏掉的部分修回来。

**教训**：stop 容差（7cm）把系统性偏差"合法化"了 —— 容差只能兜随机噪声，
**系统性偏差必须从控制回路里修**。主人靠窗口目视就能发现的 5cm 偏差，
日志里全是"success"。


## 00:20 载线修正第一版有震荡 bug（已修，待验证）

**现象**：修正后 creep 在 `dist=0.106` 卡死（8 秒 base_y 只动 1mm）。
**原因**：`atan2(横向误差, distance)` 在近距离时角度爆炸（5cm/10cm≈27°），
朝向目标剧烈摆动 → 差速底盘震荡不前。
**修复**：死区 1.5cm + distance 下限 0.15 + 朝向修正限幅 ±14° + 增益 2.0→1.2。
**状态**：代码已同步，明早启动验证横向偏差是否收敛（error_xyz[0] 应 <2cm）。

**教训**：控制环加"修正项"必须配死区+限幅，否则小误差经非线性放大成震荡。
